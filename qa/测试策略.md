# 测试策略：Tern Matt 面板 v1

> **范围假设声明**：本策略限于**系统级黑盒**——界面真相源是 `tern.ui` 节点树，真机真相源是 tern GUI + `tern ctl`。
> 单元/集成测试（`test/build.sh`，17 项 luau CLI 桩测试）是**开发侧职责**，本策略的风险评级与"已覆盖"结论均以该层已有保障为前提。
> 本项目**无 HTTP 接口、无数据库、无浏览器 DOM**——常规 Web 测试维度（API 层、浏览器兼容、CSS 视觉回归）不适用。

## 5. 深度校准与预算

```yaml
  budget_review: { approved_by: "用户裁决（2026-11-05）Q3：e2e 固化进仓库作常规门禁，同意在真机层投入" }
```

**升档/降档留痕**：
- R2（High）挂 `state` 轴，该轴按 R1 规则至少 standard；因已确认两处缺陷（`selectedMap` 顺序、seq 撞车）且状态机是唯一必经路径，升到 full。
- `reliability` / `concurrency` / `contract_integration` 挂 R1–R6 中 High/Medium 风险，按 R1 规则为 standard，未达 full —— 依据记于上。
- 无 Critical 风险被裁剪，无需额外降档留痕。

## 6. 自动化计划（提案）

| 用例组 | 建议框架 | 说明 |
| --- | --- | --- |
| 面板主流程（技能 / 任务板 / 地图 / 票 / 注入） | **已落地**：`test/e2e.sh` + `test/e2e-cases.sh`（tern ctl 驱动真机 GUI） | 已固化进仓库，8 例全绿 |
| 纯逻辑（泳道分组、前沿计算、模板渲染、frontmatter 解析） | **已落地**：`test/build.sh`（luau CLI 桩测试） | 17 项已绿 |
| 依赖失败路径（gh 未登录 / 输出非 JSON / 轮询链异常） | 手动为主 + 桩注入 | 需构造异常环境，自动化成本高于收益 |
| 真实 agent 注入 | 手动 | 需要在有活 agent 的窗口旁执行，测试窗口旁无 agent |

**不自动化清单**：并发轴的多窗口同抢 seq（需并发窗口，人工构造）；可靠轴的轮询链中断（需注入异常）。

**自动化门禁**：用户已裁决 Q3 = e2e 固化进仓库作常规门禁，`test/all.sh` 一把跑单元 + e2e。

## 7. 回归策略

**回归锚点（每次必跑）**：
- 单元层 17 项（`test/build.sh`）
- 真机 e2e 8 例（`test/e2e.sh`）：面板打开列技能 / 泳道分组 / 工具条按钮齐全 / 点技能行展开原文 / 切任务板 / 地图详情视图 / 技能注入有鼠标入口 / 注入结果回写

**按变更类型的扩展规则**：
- 改动 `host.luau` 的 `view` / `key` / `event` 段 → 跑全部 8 例 e2e（视图状态机是缺陷高发区）
- 改动 `window.luau` 的轮询或注入段 → 跑「注入结果回写」+ 全部单元（跨半边契约）
- 改动 `lib/` 纯逻辑 → 跑单元 + 「技能按泳道分组」「切任务板」两例 e2e
- 改动 `lib/paths.luau` / `lib/skills.luau` → 跑全部 e2e（技能探测是安装提示的前置）
