# 规格：Tern Matt 面板 v1

> 状态：已定稿（wayfinder 地图 [#1](https://github.com/meisijiya/tern-matt-panel/issues/1) 已清空，本规格是其折叠产物）。
> 上游决策见地图的「已有决策」；事实依据见 `docs/research/`（四份取证文档）。

## 1. 这是什么

一个 **Tern 面板插件**：把中文 mattpocock 技能包（https://github.com/devcxl/mattpocock-skills-zh ）做成游戏化的可视面板 —— 面板的操作对象是技能包，借鉴 DSH 插件的交互形态，但真源是技能包，不是插件自己。

用户打开面板能做的事：

1. **技能面板**：按技能包原生的阶段链（入口 → 规划 → 实施 → 审查与交付 → 旁路）浏览技能（默认只显示正式技能，`in-progress` / `deprecated` 可切换显示）。单击看 `SKILL.md` 原文；「注入技能」按钮把 `/skill:技能名` 填进旁边 agent 的输入框（`cx:run`，多行包括号粘贴），提交时机由用户决定；双击只复制到剪贴板。
2. **任务板**：wayfinder 的地图列表 → 地图详情（子票 / 地图级前沿 / 迷雾 / 范围外）→ 单票详情；票上按 wayfinder 票类型给出对应动作，一键把动作指令注入 agent。
3. **状态栏胶囊**：显示 `Matt <技能包版本>` 并作为面板入口，点击打开面板。

## 2. 边界

### v1 做什么

| 块 | v1 范围 |
| --- | --- |
| 技能面板 | 浏览（阶段泳道分组）、看原文、注入 `/skill:技能名` |
| 任务板 | 只读浏览（地图 → 票 → 详情），票上点动作注入指令 |
| 状态栏胶囊 | 面板入口（`Matt <技能包版本>`） |
| 数据源 | 由目标仓库的跟踪器约定文件决定：GitHub issue（`gh api graphql`）或本地 markdown（`.scratch/<工作单元>/`）；无约定文件时按 origin / `.scratch` 识别并写明依据来源 |

### v1 不做什么

- 任务板写操作（认领 / 关闭票）—— v2。
- GitLab 后端；模式切换 UI 与手动选择（模式由仓库契约决定，见 ADR-0003）。
- 插件打包 / 同步 / 镜像任何 skill 正文。
- 代装、代下载、代升级技能包。
- DSH 的版本管理页、外观调色板、六步初始化向导、多后端切换。

## 3. 架构

沿用 `D:/26code/tern-prompt-panel` 已趟平的 tern 面板骨架，不重新发明。

```
plugin.toml        插件清单：一个 block（面板）
host.luau          宿主半边：画面（tern.ui 节点树）+ 数据获取（gh 子进程、读技能目录）
window.luau        窗口半边：调色板命令、状态栏胶囊、把注入请求转交给 agent
lib/               纯逻辑（可在 luau CLI 下单测，不依赖 tern）
styles.css         排版，颜色交给主题
test/              luau CLI 桩测试 + 真机 e2e
```

### 半边分工（0.9.11 实测，issue #8）

| 能力 | 宿主半边 | 窗口半边 |
| --- | --- | --- |
| `tern.ui` 渲染 | ✅ 块就在这里 | — |
| `tern.timer` | ✅ 实测会触发 | ✅ |
| `tern.process.run`（跑 `gh`） | ✅ 三形态全通 | ✅（但 UI 线程、500ms 墙钟） |
| `tern.fs` / `tern.kv` / `tern.getenv` | ✅ | ✅ |
| `cx.agents:ask` / `cx:run` | ❌ | ✅ **注入必须走这里**（`cx:run` 只打字不提交） |
| `tern.chrome.status` / `tern.command` | ❌ | ✅ |
| `cx:copy`（剪贴板退路） | ❌ | ✅ |

**结论**：拉数据放宿主半边，注入走窗口半边，中间用 `tern.kv` 传令（宿主写 → 窗口轮询 → 执行 → 回写结果 → 戳宿主刷新）。

「注入」= 填进输入框（`cx:run`，不带回车），不是提交。早期 spec 写的「tern 没有只填输入框的接口」是错的：`tern` 的 `WindowCx.run(pane, text)` 打字不提交，带 `\r` 才会执行。

### 数据流

```
[宿主半边]                                   [窗口半边]
init/open
  ├─ 探测技能包路径 → lib/skills 读清单+正文
  ├─ gh 拉地图/票 → lib/tracker 归一化
  └─ 存 state
用户点技能/票
  └─ 写 tern.kv[action] {seq, kind, pane, body, name}
                                        └─ 轮询 (tern.timer 300ms)
                                           ├─ kind=inject → cx:run(pane, 括号粘贴的 body) 不提交
                                           │                没 agent → cx:copy(body) + toast
                                           └─ 写 tern.kv[inject_result] {seq, ok, name, error}
  └─ 读 kv[inject_result]（seq 与请求匹配才采纳）→ 改提示 + 刷新
```

> 胶囊不读任务板数据：它只显示技能包版本与打开面板的命令。版本在窗口加载/聚焦时读文件并缓存，formatter 只读缓存。

## 4. 领域模型

### 技能（Skill）

| 字段 | 来源 |
| --- | --- |
| `name` | `SKILL.md` frontmatter 的 `name`（= 斜杠命令名） |
| `description` | frontmatter 的 `description` |
| `category` | 目录所在的一级分类（engineering / productivity / misc / in-progress / deprecated） |
| `lane` | 阶段泳道（见 §5） |
| `size` | `SKILL.md` 字节数 |
| `extras` | 附属文件名列表（`agents/`、`tests.md` …），**只列名，不预读正文** |

技能组版本与技能列表同源：优先读 omp 插件安装登记（`~/.omp/plugins/installed_plugins.json`）里本技能包条目的 `installPath` 与 `version`；条目缺失时读安装副本的 `package.json`；登记里没有本包条目时才回退市场克隆目录。登记文件存在但条目读到半截/不可解析时保留上次值，不切换到别的副本。

### 地图（Map）与票（Ticket）

| 字段 | GitHub 后端 | 本地 markdown 后端 |
| --- | --- | --- |
| 地图 | issue 带 `wayfinder:map` 标签 | `.scratch/<工作单元>/map.md` |
| 票 | 地图的子 issue | `.scratch/<工作单元>/issues/NN-<slug>.md` |
| 类型 | `wayfinder:<type>` 标签（research / prototype / grilling / task） | 票文件 `Type:` 行 |
| 阻塞 | GitHub 原生依赖（`blockedBy`），全部阻塞者关闭即解除 | `Blocked by: NN` 行，只在本工作单元内解析；指向不存在的票判被阻塞 |
| 认领 | assignee 非空 | `Status: claimed` |
| 关闭 | issue 关闭 | `Status:` 为 resolved / completed / closed / done / wontfix |
| 前沿 | 打开 + 未阻塞 + 未认领 的票（两种后端同一条判据） | 同左 |
| 迷雾 | 地图正文「尚未明确」章节 | `map.md` 的 `Fog` / 「尚未明确」章节 |
| 已有决策 | — | `map.md` 的 `Decisions-so-far` / 「已有决策」章节 |
| 范围外 | 地图正文「范围外」章节 | `map.md` 的 `Out-of-scope` / 「范围外」章节 |
| 规格 | 带 `ready-for-agent` 且无父 issue 的 issue | `.scratch/<工作单元>/spec.md` |

两种后端产出同一套归一化结构；身份都是字符串（GitHub 是编号，本地是 `<工作单元>/<NN>`），因为各工作单元的编号会重号。迷雾、已有决策、范围外都只呈现文字，不解析成结构。

本地后端一次扫描把文件读进内存，分组、统计、前沿全从内存算；地图与规格容器不计入票统计；某张票读不动时界面报「N 个文件读不动」并列出文件。面板不改跟踪器数据：写由 agent 按注入模板落笔，人用「打开文档」（本地后端才有）在 tern 文档视图里改。

### 阶段泳道（lane）

**直接取自技能包，不自造分类。**

| 泳道 | 技能 |
| --- | --- |
| 入口 | `ask-matt` `triage` `diagnosing-bugs` `wayfinder` `grill-with-docs` |
| 规划 | `to-spec` `to-tickets` |
| 实施 | `implement` `implement-spec` `tdd` |
| 审查与交付 | `code-review` `pr` `retro` |
| 旁路与专项 | 其余全部（research、prototype、wizard、handoff、teach、writing-* 等） |

泳道内的顺序按目录列举顺序排（不承诺阶段顺序）；`in-progress` / `deprecated` 分类默认隐藏，可切换。

## 5. 交互

### 面板结构

**单块 + 顶部视图切换**：技能 / 任务板 / 技能包 / 地图详情 / 票详情五态（地图 issue #1 决策；技能包视图见下文）。

理由：tern.ui 无独立标签页原语；多块并列会让用户同时开多个面板。单块切换与 tern-prompt-panel 的 browse/search/edit 模式切换同款。

### 认不出仓库时

面板默认按当前目录的 git remote 认仓库，每次打开都会重新推断（手动覆盖只按窗口保存，不写全局）。
推不出来就清空票与地图，显示 setup 卡：失败原因 + 「目录要有 .git 且配了 origin」+「手动指定 owner/repo」。
「换仓库」可填 `owner/repo` 或 GitHub 链接，覆盖只对本窗口生效并保留到「重置仓库」；重置后回到 cwd 的 remote。

### 操作方式：以鼠标为主

面板的全部操作都有鼠标入口，底部只提示鼠标动作。

键盘处理代码仍在：`Tab` 在真机上实测可切换视图，说明 key 事件到得了宿主。
其余键（`↑`/`↓`/`Enter`/`i` 等）未在真机验证过 —— 验证时窗口正处在 GPU 设备丢失、
停止重绘的状态，结论不可靠。在重新验证之前，界面不宣传键盘操作。

### 票的动作（票类型 → 注入内容）

| 票类型 | 动作 | 注入内容 |
| --- | --- | --- |
| `wayfinder:grilling` | 盘问 | 盘问模板（`/skill:grill-with-docs` + 票链接 + 目标/事实核验/边界/交付） |
| `wayfinder:prototype` | 原型 | 原型模板（`/skill:prototype` + 票链接 + 同上骨架） |
| `wayfinder:research` | 调研 | 调研模板（`/skill:research` + 票链接 + 同上骨架） |
| `wayfinder:task` | 执行 | 执行模板（不挂技能 + 任务标题与链接 + 同上骨架） |
| 任意 | 打开链接 | 浏览器打开票 |
| 任意 | 复制票信息 | 票标题 + 链接 |

票动作注入的正文套注入信封，开始行带 `· #票号`（见下文「注入」）。

工具条常驻五个按钮：新增需求（两条路：wayfinder 画地图 / grill-with-docs 收敛 spec）、提 BUG（wayfinder 建 bug 票，五项索取要素 + 建单前查重）、体检（游离票归位，先出清单再动手）、收尾（一段工作的工程化收口，见下）、技能包（切到技能包视图）。

### 收尾动作

「收尾」是仓库级动作，不绑定票号。它声明用户已手工验收通过，并把这轮工作按七段串行收口：

| 段 | 做什么 | 出口判定 |
| --- | --- | --- |
| 1 盘点现状 | `git log <固定点>..HEAD --oneline`、`git diff --stat`、`gh pr list`，改动对到票号 | 列不出或对不上 → 停 |
| 2 审 diff | `/skill:code-review` 双轴（规范 / 规格）；固定点先自推并写明依据 | 有未处理发现 → 修完重审 |
| 3 文档更新 | 规格 / 术语表 / ADR / `AGENTS.md` / README 与实现对齐，作废段落删除 | 三者冲突 → 报冲突，不选边 |
| 4 清理与收拢 | 奥卡姆剃刀；死代码、临时文件、未并入主线的分支 | 删除清单等用户点头 |
| 5 交付 | `/skill:pr` 写 body；合并是单向门 | 建 PR 前问，合并等用户 |
| 6 复盘 | `/skill:retro` 规则（导航 / 自动化检查 / 规范 / AGENTS 体积 / 工具经济性 / 空操作 / 信息访问） | 改规范类先提议 |
| 7 报告与交接 | `/skill:answer-me-with-html` 出七段报告；`/skill:handoff` 写系统临时目录 | 报告路径可打开、交接路径已写进报告 |

`retro` 与 `handoff` 的技能元数据禁止模型自动调用，模板同时内联其规则摘要：命令可用走技能，不可用按摘要执行。任一外部包缺装时收尾仍可注入，缺的步骤走降级路径（无可视化则出 Markdown 报告并注明原因）。收尾期间发现真问题就暂停，回到开发或建 BUG 票。

### 技能包视图

面板引用三套外部包：mattpocock 技能组、answer-me-with-html（可视化报告）、omp-skill-forge（选路表与分支、发布、评审技能）。视图是独立一态，每套一张卡：

- 名称 · 版本 · 状态（未装 / 已装 / 待更新 / 已是最新 / 本地较新 / 无法比较 / 检查失败 · 上次 <时刻>）· 上游最新版本（查到才显示）· 用途一句 · 仓库链接 · 安装指引（逐行可复制）。
- 发现方式：前两套按 omp 安装登记的键找 `installPath`（版本取登记，缺失回退安装根的 `package.json`）；omp-skill-forge 不在登记里，按本地安装根目录探测。
- **自己的刷新**：打开视图只读本地状态、不发网络请求；点「刷新版本」才逐套查上游 release，5 分钟节流，失败保留上次结果。该刷新不触碰任务板数据与任务板刷新时刻。
- 安装指引照抄上游原文，不自造命令。

任务板顶部另有「问下一步」：把 `/skill:ask-matt` 与一段提示词填进输入框（核事实的方式、判断顺序、交付形状），由会话自己用 `gh` 核事实并给建议。面板不搬任务板快照、不做判断、不发任何模型请求。

模板只替换仓库名这一个占位符，其余文字固定。判断所需的事实由会话自己用 `gh` 核：开放的票与依赖、`git status`、仓库里的 `GLOSSARY.md` / `docs/adr/` / `docs/spec/`。面板不搬任务板快照，避免面板与仓库两份数据打架。

正文不含任何置信度、新鲜度或不确定表述；抓取时刻只用于面板底部的状态提示。

输出契约写进正文：最多 3 条，每条一行「做什么 · 用哪个技能命令 · 第一步具体动作 · 一句依据」，末尾写明哪几项没核到。

顶部工具条按面板宽度换行：按钮装不进一行就折到下一行，任何宽度下都不裁掉按钮。

**不做** DSH 那套按 triage 标签（needs-triage / ready-for-agent / bug …）分类的动作 —— 那是本仓库 issue 的分类轴，与 wayfinder 票的决策类型轴不同轴。

### 注入

- 注入内容：技能 → 一行 `/skill:技能名`（omp 只认这个前缀）；票 → **插件自带的动作模板**渲染结果（模板硬编码在插件内、随插件分发、中文单语）。
  模板文件化与用户覆盖留 v2 —— 当前十条模板硬编码，引入文件读取会新增一条「用户写坏模板」的失败路径。
- **注入信封**：模板注入（两个入口、四个按钮、四个票动作）都经 `lib/commands.luau` 的统一出口 `buildInjectionBody(action, body, number?)` 产出，正文套一层信封：
  ```
  ===== 注入开始 · tern-matt-panel · {动作名}[ · #{票号}] =====
  {正文}
  ===== 注入结束 · 下面是用户输入的内容 =====
  ```
  票类注入有票号时开始行带 `· #编号`；正文为空不产出信封，也不出注入请求。
  信封尾：结束行之后追加一个换行，用户补充从下一行开始。该换行属于信封正文，位于括号粘贴序列内部；粘贴结束标记之后不得再有换行（那等于回车会直接提交）。技能单行注入不加换行。
  动作名取值：问下一步、提 BUG、体检、收尾、入口·还没想清楚、入口·需求已明确、盘问、原型、调研、执行。
  信封内是面板填好的内容，用户不改；用户的需求写在结束行之后 —— 模板末节声明「结束行之后的文字是用户输入，按它执行；与上面冲突时以用户输入为准」。
  技能单行注入（`/skill:名字`）不套信封，仍是一行。
- 模板**不得内嵌任何 skill 正文**，只能以"调用某个已安装技能"的方式提及（`/skill:grill-with-docs` 即合规 —— omp 只认 `skill:` 前缀）。
- 模板正文里不留待填空位；需要用户讲的内容写成末节的描述性说明，缺的按 needs-info 标记并回问。每条模板共用一段「反问（信息不全时先问）」小节，反问走 `/skill:grilling`（盘问票、「需求已明确」入口与收尾本身已有自己的流程，不重复调用）。
- 通道：宿主写 kv → 窗口轮询 → `cx:run`（只打字，不带回车）。多行正文包成 `\27[200~…\27[201~` 括号粘贴，终端当一次粘贴处理，不会在第一个换行处提前发出。提示词一律只填进输入框，由用户补完自己提交。没有邻近 agent 时复制到剪贴板 + toast，不失败。
- **旁路通道**：窗口命令「技能速览」是第二条注入路径 —— 它弹一个选择列表后**直接** `cx:run` 填进输入框，不经 kv、不带 pane 归属。它不与面板抢 pane，保留为快速入口。

### 未安装技能包时

面板技能区显示**安装提示**，指向 https://github.com/devcxl/mattpocock-skills-zh ，并给出可操作安装指引（命令或步骤）。任务板区仍正常工作（任务板不依赖技能包）。

## 6. 插件自带的资产（不是 skill）

- 票动作与常驻按钮的提示词模板（硬编码在 `lib/templates.luau`，中文单语），占位符只有仓库名与仓库根。这些是**插件自有配置**，不含任何 skill 正文。十条模板共用两句口径：第一性原理与角色句。
- 外部技能包清单（硬编码在 `lib/packs.luau`）：显示名、发现方式、仓库链接、安装指引原文、用途一句。只读探测，不代装。
- 分类泳道表 —— 技能名到 lane 的映射表（插件自带，因为包本身不声明 lane；lane 依据包的阶段链推导，见调研文档 §3.2/§6.1）。

**插件绝不把任何 skill 正文复制进自己的仓库或插件数据目录。** 技能组始终是外置、随上游走的单一真源。

## 7. 数据源与刷新

- **仓库**：默认跟随当前工作目录的 git remote 推断（`git remote -v` → `owner/repo`）。「换仓库」可填 `owner/repo` 或 GitHub 链接，切换只对当前窗口生效并保留到「重置仓库」；重置后回到 cwd 的 remote，手动刷新即可。
- **权限**：v1 只有读路径，read 权限足够，不做权限探测。账号权限边界留 v2（届时随写路径一起解决）。
- **刷新**：**打开即拉一次 + 手动刷新按钮/`r` + 切回面板所在 tab 时按 5 分钟节流自动刷**。没有后台定时轮询（票是低频变化，定时轮询白耗 gh 配额）；聚焦只是「可能要看数据」的信号，真正拉不拉由宿主按上次请求时刻判定，正在拉、失败冷却中、距上次不足 5 分钟都不发请求。底部常显「数据 HH:MM」；距上次成功拉取超过 2 小时时该时刻用错误色并追加「· 建议刷新」，不再随年龄升级、不弹窗。旧缓存只有字符串时刻、没有秒级时间戳时不判陈旧。数据存宿主 state，每次刷新整份替换。
- **刷新不清屏**：已经有票/地图时，刷新期间继续显示旧内容，只有空板才显示「正在拉取…」——否则每次焦点切换触发的刷新都会让面板闪一下。
- **拉取分页**：open 与已关都走 GraphQL 游标查询（`orderBy` 指定创建时间方向，`pageInfo.hasNextPage/endCursor` 决定续拉）。open 每页 50、循环到 `hasNextPage=false`（前沿判定需要每张 OPEN 阻塞票在场）；已关首屏一页 50。排序方向映射到上游（最新在前 DESC / 最早在前 ASC），面板只按上游顺序追加，已加载的部分不跨页重排。
- **加载更多**：已关组末尾显示「加载更多（已 N 条）」，点一次续拉一页并追加；累积上限 500，到上限或上游没有下一页时该行消失。切排序或刷新时已关组丢弃已加载页、回到第一页按新方向重拉。分页游标与已加载条数不跨面板块持久化，重开面板从第一页开始。
- **地图归组边界**：地图只从本批已加载的票建卡。已关地图尚未加载到时其卡不出现，它的 open 子票仍会进入四组；这是分页下的预期退化。
- **拉取失败时的退路**：拉取成功时把已加载 issue 存一份缓存；下次拉取失败（最常见是 GitHub 限流）时**退到缓存继续显示**，提示文字注明「显示上次拉到的数据」及时刻。续拉失败只提示，保留已加载内容，不清屏。没有缓存才显示空列表。
- **拉取方式**：GitHub 后端走 `gh` CLI 子进程（宿主半边，`tern.process.run` 三形态实测全通）。列表与依赖用 `gh api graphql`；票正文、地图正文（迷雾/范围外）在点开时用 `gh api repos/<repo>/issues/<n> --jq .body` 单取。地图刷新重建后若仍停在地图页，会补拉当前地图正文。
- **后端判定**：读目标仓库的 `docs/agents/issue-tracker.md`，只认高置信标题行（`# Issue tracker: …` / `# Issue 跟踪器：…`）；没有约定文件时按可观察证据识别（origin 指向 GitHub → GitHub，存在 `.scratch/` → 本地 markdown），并在界面写明「按约定文件」/「按识别」。面板不提供模式切换、不保存手动选择（模式是仓库的属性，见 ADR-0003）。彻底判不出时出 setup 卡，提示先跑 `/skill:setup-matt-pocock-skills`。
- **本地 markdown 后端**：一次扫描 `.scratch/` 下每个工作单元（有 map.md / spec.md / issues/ 任一即算），门票与地图文件读进内存；规格单独成顶层卡；扫描结果不含用户输入拼接的路径。「打开文档」把票 / 地图 / 规格文件调进 tern 文档视图（`cx.docs:open`，窗口半边），并提示「该文件 agent 也会写」；GitHub 后端不显示该按钮。
- **远程地址解析**：本地路径形状的 remote（盘符、绝对路径、`..` 开头、`file://`）一律判解析不出，落到 setup 卡，不去请求远端。

## 8. 状态栏胶囊

显示 `Matt <version>`，点击打开面板。版本是包级信息、不随 tab 变；票数随当前 tab 的仓库变，不在胶囊里显示。窗口加载时读一次版本，每次窗口获得焦点时重读并刷新状态栏；formatter 只读缓存，不做文件读。没装技能包或读不到版本时退成 `Matt`，不显示「未知版本」或占位符。

## 9. 验收

1. `tern plugin list` 末尾是 `ready`，不是 `failed`。
2. 面板按泳道分组列出**默认可见的正式技能**（`in-progress` / `deprecated` 隐藏），切 `s` 后显示全部探测到的技能；显示技能组版本。技能数量不写死（上游会变）。
3. 技能详情能显示 `SKILL.md` 原文。
4. 任务板能列出 `wayfinder:map` 地图与子票，算出前沿（未关闭未阻塞未认领），显示阻塞关系与迷雾/范围外两节文字。
5. 点技能的「注入」能把 `/skill:技能名` 送进邻近 agent 的输入框（或在没有 agent 时复制到剪贴板并提示）。
6. 点票的动作能把模板渲染结果送进邻近 agent。
7. 状态栏胶囊显示 `Matt <技能包版本>`（取自 omp 安装登记，与本机 agent 加载的副本同源），点击打开面板；没装技能包时显示 `Matt`。
8. 探测不到技能包时，技能区显示安装提示（带仓库链接与安装指引），任务板仍可用。
9. 插件目录与插件数据目录里**不含任何 skill 正文副本**。
10. `test/build.sh` 全绿（纯逻辑部分）。
11. 面板变窄时顶部工具条换行，按钮全部可见可点；所有视图都不裁按钮。
12. 「问下一步」「提 BUG」「体检」「收尾」注入的正文套着注入信封：以 `===== 注入开始 · tern-matt-panel · {动作名} =====` 开头、以 `===== 注入结束 · 下面是用户输入的内容 =====` 加一个换行收尾，信封内是模板正文（自含判断顺序与交付形状，不含任务板快照）；用户的需求从结束行下一行开始写。
13. 切回面板所在 tab 会触发一次数据检查（只戳该 tab 里的面板，别的 tab 不跟着刷），但 5 分钟内的重复聚焦不再发请求；已有数据时刷新期间不清屏。
14. open 票翻页拉全；已关票首屏 50 条，组内「加载更多（已 N 条）」每次续拉一页、追加去重，到 500 条或没有下一页时消失；切排序/刷新回到第一页按新方向重拉，已加载部分不跨页重排。
15. 已关地图未加载到时其卡不出现，但其 open 子票仍在四组里，面板不报错。
16. 底部「数据 HH:MM」距上次成功拉取超过 2 小时时用错误色并追加「· 建议刷新」；旧缓存只有字符串时刻时不判陈旧。
17. 任务板拉取失败保留已看到的数据并标注数据时刻；续拉失败保留已加载内容，不清屏。

18. 「收尾」在任一视图都可见；点它在没识别到仓库时给提示、不注入；注入正文含七段、出口判定、越权禁令、报告七段与交接要求，技能命令写成 `/skill:名字` 且前后留空格。
19. 技能包视图列出三套外部包，版本分别取登记与本地 `package.json`（登记缺失时回退插件缓存里的同名副本）；缺装的卡显示「未装」并给出可复制的原文安装指引；缺装时收尾仍可注入。
20. 视图内「刷新版本」逐套查上游 release：本地落后显示「待更新」，相同显示「已是最新」，失败保留上次结果并标「检查失败 · 上次 <时刻>」；所有版本检查文案统一以「版本检查：」开头（进行中 / 已查 N 套 · M 套待更新 / 刚查过 / 没有已安装的技能包）。release 查不到时回退仓库 tags。刷新不动任务板数据与刷新时刻。
21. 窄面板下五个常驻按钮与视图按钮换行后全部可见可点。
22. 目标仓库的约定文件声明本地 markdown 时，面板按 `.scratch/` 显示地图与票，任务板顶部写明后端与依据来源；全程不发 `gh` 请求。约定文件声明 GitHub 时行为与上面各条一致。约定文件缺失时按 origin / `.scratch` 识别；两者都没有时出 setup 卡。
23. 本地后端：认领过的票（`Status: claimed`）进「已认领」而非「可领」；resolved / completed / closed / done / wontfix 进「已关闭」；`Blocked by:` 指向不存在的票判「被阻塞」。
24. 本地后端：同仓库不同工作单元的同号票分别显示、互不覆盖；地图与规格容器不计入票统计；读不动的文件报数并列出路径。
25. 本地后端：票详情原样显示票文件全文，状态另起一行（开合 · 认领 · 类型 · 坏阻塞引用）；地图详情显示迷雾与已有决策两段，不显示笔记段；规格单独成卡。
26. 本地后端：注入正文出现仓库相对路径与读文件动作，全文不出现 `gh issue view` / `gh issue list`；GitHub 后端的模板正文逐字不变（模板体只有一份，后端差异在占位变量里）。
27. 本地后端：票、地图、规格三处都有「打开文档」，点它调出 tern 文档视图；GitHub 后端不出现该按钮。
28. 远程地址是本地路径形状时面板判「解析不出」并给 setup 卡，不出现远端请求失败。

## 10. 已知风险

- `gh api graphql` 的响应字段随 GitHub GraphQL schema 变化。解析要容错，字段缺失时降级显示而不是崩。
- 宿主半边拉 `gh` 会占 2s Lua 预算；open 全量翻页在超大仓库（数千 open 票）会拉多页，需要时再改成分批或按需。
- 技能包版本随上游走，插件自带的 lane 映射表可能与新版本对不上：未在映射表里的技能落到「旁路与专项」，不报错。
- 上游 `mattpocock-skills-zh` 与本机已装副本可能不同步（实测两处副本存在 in-progress 差异），面板以探测到的为准并显示版本。
- 收尾依赖两件未在真机验证过的事：`answer-me-with-html` 的 `am` CLI 需要 Node ≥20；`retro` / `handoff` 的元数据禁止模型自动调用。前者跑不起来时退 Markdown 报告，后者由模板内联规则兜底。
- 技能包的版本检查各自消耗一次 `gh` 调用，三套共享配额；只在手动刷新时发生，并用 5 分钟节流。
