# 规格：前端设计入口（三条路线）

> 上游决策见地图 [#58](https://github.com/meisijiya/tern-matt-panel/issues/58)；本规格是它的折叠产物。

## 问题陈述

用户在做前端时说不清设计术语：脑子里有「鼠标放上去变个色、点下去要有反馈」的画面，却不知道这对应 Hover、Active、Transition，也不知道该让 agent 看哪个组件形态。AI 生成的前端常带模板感与 AI 味，用户没有词去纠正。

设计决策也留不下来：这次选的颜色、字体、间距与组件规则散在会话里，下次改同一个页面又要重新解释，前后不一致。面板已有技能、任务板、收尾与技能包视图，但没有一个入口把「把需求说准」「给可视化选项」「把设计沉淀下来」连起来。用户只能临场敲提示词，每次都从头来。

## 解决方案

在工具条新增「前端」按钮，点开三条路线：

- **新建设计**：从 0 到 1 确定视觉方向，用户选定后把设计决策写进目标仓库根部的 `DESIGN.md`；整站路线可落页面骨架与样式，不写业务逻辑与接口。
- **设计迭代**：在已有页面上改视觉或组件，先读 `DESIGN.md` 与现有实现，只更新变更的 token。
- **只解释术语**：不读仓库、不改文件，把模糊描述改写成准确需求，并给 1~3 个术语与可视化解释。

三条路线都通过既有的注入信封把模板送进邻近会话；模板只引用已安装技能，不内嵌任何技能正文。技能包视图新增 taste-skill 与 vibehub，按 Magpie、skills CLI、marketplace 多通道识别；README 统一致谢引用到的技能。

## 实现决策

### 接缝

- 沿用三个既有接缝，不新增模块：模板注册表、注入命令构造与宿主动作分发、技能包清单与宿主探测。
- 最高接缝是「模板」与「技能包清单」：三条路线只是模板注册表的新记录；两个新包只是技能包清单的新行。工具条与注入管线不需要新抽象。
- 技能包视图只展示包卡，不展开技能列表；因此 taste-skill 没有分类层不影响本次。

### 工具条与入口

- 工具条新增「前端」，位置在「新增需求」旁边。
- 点击「前端」展开三张路线卡；再点收起；选一条后注入并收起。
- 三条路线复用现有动作分发与注入函数；不新增文本输入框，不新增视图。
- 无仓库时：「新建设计」「设计迭代」提示先识别仓库、不注入；「只解释术语」照常注入。
- 本地 markdown 后端算已识别仓库，两条设计路线照常可用。

### 模板

- 新增三份模板记录，标题分别为「新建设计」「设计迭代」「只解释术语」；注入动作名为 `前端·新建设计` / `前端·设计迭代` / `前端·只解释术语`。
- 三份模板共用轻量反问小节：只走 `/skill:grilling`，加仓库文件与 `git status` 事实；不挂 `forge-router` / `research` / `gh` 公共段。
- 三份模板都声明「不替用户拍视觉方向」「不建 PR / 不提交」；业务边界按路线分开：两条设计路线不写业务逻辑与接口（页面骨架、组件样式属于设计交付），只解释术语不读仓库、不改文件。
- 三份模板都声明用户输入优先：结束行之后的文字按它执行。
- 不引用 `frontend-design` 与 `impeccable`；taste-skill 已覆盖视觉方向，避免重复依赖。
- 不按 React / Vue / 静态 HTML 预设分支；先读项目栈再适配。

### 新建设计

- 先判场景：整站/落地页还是单组件；判不准就问。
- 先问清业务、页面类型、主行动、目标用户。
- 给 2~3 个视觉方向，每个一行：定位、适合什么、代价；先不写代码。
- 用 answer-me-with-html 出方案页，放 `ask` 选择；每组 2~6 个选项，推荐项用 `*`；缺装退 Markdown 表。
- 用户选定后才写 `DESIGN.md`。写前问一句；已存在时问「更新还是另起」，不覆盖。
- 整站/落地页走 taste-skill 全链：先 `gate.mjs --start …` 装门，再跑 `gate.mjs <页面>` 并读 `GATE:` 行；首次算第 1 轮，最多 3 轮。单组件只跑 `copy-lint`（仅英文文案）与局部检查，不跑整门。
- 防 AI 味：中文引用 `lieflat-less-ai-tone`（若已装）；英文用 taste-skill 的 `copy-lint`；只给防 AI 味页面链接，不内联条目。
- 出口：用户没选方向、`DESIGN.md` 已存在且未决定更新/另起、`DESIGN.md` 与代码 token 冲突 → 停；外部技能缺装、校验失败 → 报告并继续。

### 设计迭代

- 先读 `DESIGN.md` 与现有组件/样式入口；判改的是 token、组件还是页面结构。
- 给改动前后 2~3 个方案，用 answer-me-with-html 出方案页 + `ask`；缺装退 Markdown。
- 用户选定后只更新变更 token；缺 `DESIGN.md` 先问、不自动建；已存在不覆盖整份；冲突只报告。
- 尽量跑设计文件校验与 `diff`；失败只报告，不阻塞。
- 不跑 taste-skill 整门；只借 `copy-lint` 与局部检查。
- 出口：用户没选改动、缺 `DESIGN.md` 且未决定创建、冲突 → 停；外部技能缺装、校验失败 → 报告并继续。

### 只解释术语

- 不读仓库、不跑 git、不改文件、不写 `DESIGN.md`。
- 用 vibehub 查 1~3 个稳定术语；只采用返回的链接；缺装退纯文字 + 链接；没有可靠匹配就说明，不硬塞。
- 把需求改写成可直接发的话；保留原意，不擅自加框架、参数或实现方案。
- 用 answer-me-with-html 出术语解释页 + `ask`（可选）；缺装退 Markdown。
- 出口：没有可靠匹配、vibehub 缺装、am 缺装 → 各自降级；用户只要解释不要改写 → 按用户。

### `DESIGN.md` 生命周期

- 位置：目标项目根 `DESIGN.md`；不跟随 `docs/design/`，避免两份。
- 新建设计以 `DESIGN.md` 为真源；需要 Tailwind/CSS 时用外部导出命令生成，不手写第二套。
- 设计迭代以现有代码优先，反填 `DESIGN.md`；只更新变更 token；迁移期不双写。
- 内容：front matter 用版本标记、名称、至少一个主色；按需加颜色、字体、圆角、间距、组件 token。正文按固定顺序的八个章节，可省略但顺序不能乱；写设计理由、组件规则、禁用项，不写实现细节。
- 创建：用户确认视觉方向后写；缺文件先问，不自动建；已存在不覆盖。
- 确认：agent 起草，用户点头才落盘；用户明确说「直接写」才跳过。
- 冲突：与代码实际 token 不一致时报告并列出假设，不选边。
- 版本：不做 changelog，不写「最后更新」行；git 历史即版本。
- 校验：尽量跑 `lint`；迭代跑 `diff`；失败只报告，不阻塞。
- 面板不读取、不展示 `DESIGN.md`。

### 技能与技能包

- 模板引用：`design-taste-frontend` 只在新建设计与设计迭代引用；`answer-me-with-html`、`vibehub` 三份都用；共用 `grilling`（只解释术语用不含 gh/git 自查的反问变体，因为它不读仓库）；可选 `lieflat-less-ai-tone`。
- 技能包清单新增 `taste-skill` 与 `vibehub` 两行；各有仓库、用途、安装指引、探测路径。
- 发现链：安装登记 → Magpie 软链目录 → skills CLI 全局目录 → skills CLI 项目目录 → Claude 技能目录 → marketplace 缓存兜底。
- 版本来源：登记版本 → `package.json` → 技能 frontmatter 版本 → 「未知」；「未知」不等于「未装」。
- 软链：跟随软链目标读版本；断链或目标不存在标「未装 / 不可读」，不崩。
- 多副本：同一技能只出一行，按发现链优先级取版本。
- 不设最低版本门槛；安装指引照抄上游原文；marketplace 只在上游有明确方式时出现。
- 面板只读探测，不代装、不代下载。

### 防 AI 味

- 不爬防 AI 味页面并固化；不内联 25 条条目或「判断动作」清单。
- 模板只给页面链接作人工参考；中文成稿引用 live 技能；英文页面用 taste-skill 的 `copy-lint`。
- 维护责任留在 live 技能与页面；模板只写「检查过或明确跳过并注明」。

### 文档与许可

- 产品规格、术语表、README 同步更新。
- 术语表新增：前端入口、新建设计、设计迭代、只解释术语、设计沉淀。
- README 新增「致谢 / Attribution」：列 mattpocock 技能组、answer-me-with-html、taste-skill、vibehub、lieflat-less-ai-tone、omp-skill-forge；每项给显示名、仓库链接、许可证；写明不内嵌技能正文。
- 许可口径：非商用、开源自用、不收费；CC BY-NC 只引用，不内联。

### 注入与状态

- 三条路线都经统一注入出口，套既有注入信封；开始行带动作用名；正文为空不注入。
- 注入只填输入框，不自动提交；失败走既有剪贴板退路。
- 不新增面板状态字段以外的结构；不新增视图。

### 回滚

- 纯增量：删除三份模板、三个动作、两行包登记即可回到现状；无数据迁移。

## 测试决策

- **测试接缝**：新增一个前端专用纯逻辑测试文件，并入现有门禁入口；真机 e2e 继续用受控窗口，不为本功能另起窗口。
- **好测试的定义**：只测外部行为——模板是否含必需标记、是否含禁止标记、动作名是否正确、包探测是否按优先级、版本兜底是否正确、信封是否正确；不断言整段文案逐字不变。
- **单元测试覆盖**：
  - 三份模板存在，标题与动作名正确。
  - 三份都含反问、用户输入优先、出口判定；都不含 `forge-router` / `research` / `gh` 公共段。
  - 新建设计含 taste-skill、am、vibehub、`DESIGN.md`、门禁、`copy-lint`、防 AI 味链接与 live 技能。
  - 设计迭代含 `DESIGN.md`、`lint`、`diff`、`copy-lint`，不含整门全链。
  - 只解释术语含 vibehub、am，不含 taste-skill，含「不读仓库、不改文件、不写 `DESIGN.md`」。
  - 三份都不含 `frontend-design` / `impeccable`，都不含防 AI 味条目标题。
  - `DESIGN.md` 四条：缺文件先问、不覆盖、冲突只报告、校验失败不阻塞。
  - 包清单两行；发现链优先级；版本兜底；「未知」不等于「未装」；多副本一行；不设版本门槛。
  - README 致谢六项齐全，含仓库与许可证，且不含技能正文。
- **真机 e2e 覆盖**：
  - 「前端」在「新增需求」旁边；窄面板换行后可见可点。
  - 点开三张路线卡，再点收起；三条各注入一次，信封与动作名正确。
  - 无仓库：前两条提示、第三条照常。
  - 技能包视图五套包；两个新包卡片有状态、版本、链接、安装指引；不展开技能列表。
  - 软链夹具与断链夹具；不崩、不误报。
  - 本地 markdown 后端：三条路线可用。
- **人工验收**：新建一个小页面、迭代一个已有组件、只解释一个术语；看方案能否选、`DESIGN.md` 是否只在确认后写、术语是否不硬塞、链接是否不伪造。
- **门禁**：纯逻辑测试与 `luau-analyze` 全绿；受控窗口 e2e 通过；不新增 flaky；不推送、不建 PR、不合并。
- **先例**：现有模板与技能包单测、受控窗口 e2e 的断言方式；本功能沿用同一套断言风格。

## 范围外

- 面板读取、展示或编辑 `DESIGN.md`；版本历史与可视化编辑器。
- 非 Web 前端（桌面端、移动端原生）的设计流程。
- Figma / Sketch 集成、图片生成、图标库采购。
