# 任务板双后端，模式由仓库契约决定

- **Status**: accepted

任务板有两个数据源：GitHub issue（`gh` CLI）与本地 markdown 跟踪器（上游 `.scratch/<工作单元>/` 约定）。**用哪个后端由目标仓库自己的跟踪器约定文件决定** —— 面板读那份约定文件来判定，不提供模式切换按钮，也不提供手动覆盖；约定文件缺失时按可观察证据识别（有 origin 指向 GitHub → GitHub，存在 `.scratch/` → 本地 markdown），并在界面上写明依据来源。理由：跟踪器是仓库的属性，不是面板的属性；插件若自己持有选择，就会出现第二份与仓库不一致的状态，且用户改仓库的跟踪器后插件还按旧选择走。

面板**不改跟踪器数据**。写只有两条路：agent 按注入模板落笔（面板只递纸条并显回执与失败退路），或人用面板上的「打开文档」入口调出 tern 的文档视图自己改盘上的文件（平台自带撤销、自动保存、原子写）。理由：上游这套技能的设计原则是不接管流程、保留人的控制权；面板一旦自己能改票，就要自造并发写仲裁、冲突处理、写失败回滚与路径越权防护，而参考实现的写路径基建（写回执、写模型锁、诚实冲突、通知中心）正是为这些付出的代价。

注入模板按后端出两套语义（引用、读票、读写票、查重、写边等处），但**模板体只有一份** —— 后端相关的句子抽成占位变量，渲染时按后端注入取值；local 后端的措辞按上游契约写（建单 = 新建票文件并写 `Status:` / `Type:` 行，归位 = 移动票文件，收尾第一段只列 git log / diff），上游契约里没有的东西（标签、认领人、原生依赖边、PR）一律不发明。

与 ADR-0002 的关系：0002 的「不做通用 tracker 抽象层」保留 —— 实现方式是新增一个本地后端解析器，产出与现有归一化结构同构的数据，分类、前沿、排序、规格归组原样复用；0002 的「单后端」被本 ADR 取代。本 ADR 与 ADR-0001（技能内容外置）无冲突。
